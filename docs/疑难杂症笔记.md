# 疑难杂症笔记

## 2026-10-19：普通模式无 Root 仍直接创建闹钟

**现象**：用户未授权共存测试版 Root，普通模式却在 ColorOS 时钟里创建了闹钟，没有进入预期的新建编辑页。此类反馈在历史版本出现过。

**原因**：标准 `ACTION_SET_ALARM` 不需要 Root。`EXTRA_SKIP_UI=false` 也不等于“只打开待保存的编辑页”。已归档的 ColorOS 16.19.14 接收代码，在带 `HOUR` 时先创建，缺少 `HOUR` 且 extras 非空时才打开编辑页。因此不要再把“设置 SKIP_UI=false”当成这个问题的完整修复。

**裁决与修复**：用户接受手动填写推荐时间并保存。对已知的 ColorOS 接收组件省略 `HOUR/MINUTES`，仍传非空 extras 和 `SKIP_UI=false`，并在界面说明手动填时分。其他时钟维持预填请求。防回归入口：`RootModePermissionTest.coloros_editor_request_omits_time_while_other_clocks_keep_prefill`。模拟器参数断言不代表厂商编辑页实机验收。

## 2026-10-19：模式偏好不能代替 Root 授权

**原因**：原切换方法先保存 Root 模式，再做失败静默的预热。用户选了 Root，就会看到 Root 模式，而不一定拥有权限。

**修复**：兼容性检查、显式申请、结果核验成功后才提交模式；失败保持普通，告知管理器授权路径。旧偏好重启后也重新检查；保留每次写入前的核验。取消／超时递增请求编号，迟到的授权结果不能改回 Root。必须先写好结果，再解除等待标记，避免外部观察到“等待结束但结果尚未提交”。防回归：`RootModePermissionTest`。

## 2026-10-19：UI 回归误读与测试程序撞包

- 失败截图已显示“小睡”，旧无障碍缓存却将五个选项都报为未选中。重新读取后的树正确标记“小睡”。测试在 API33+ 查询前调用 `UiAutomation.clearCache()`，保留真实 selected 断言，不用颜色代替状态检查。
- 设置页标题滚出屏幕后，测试误判页面并选中了内嵌滚轮。统一沿页面左侧空白区滚动，刷新树再查目标，避免略过列表项。
- 共存包使用 `com.example.smartalarm.test`；Android 默认仪器测试包也会用这个名字。仪器程序现独立为 `com.example.smartalarm.instrumentation`，两处测试入口同步，避免安装测试程序时替换共存版。

本轮结果与未验收项见 [1.4.1 报告](1.4.1/REPORT.md)。

## 2026-10-19：卡片滑动误切换与动画类问题测不出

**现象**：1.4.1 里轻轻滑一下下面的卡片，上方模式整个切换，上下不同步；上方滑块切换时文字颜色瞬间翻转，很僵硬。

**原因**：松手判断是「速度够快就切」，没有最小距离；滑块文字颜色按「已选中」而不是滑块块的实际位置变化。1.4.1 的 31 项回归全部通过，是因为模拟器的 `animator_duration_scale` 默认是 0，所有过渡动画都被跳过，测试从未看到过动画中间状态。

**防回归**：动画类测试必须显式设置动画倍率（正常用 1，要看中间画面时放慢到 10，另测 0），并在结束时还原；用轮询截图抓「滑块块刚起步」那一帧，不要靠固定等待。RED 基线与取舍见 [1.4.2 报告](1.4.2/REPORT.md)。测速用 `addPointerInputChange`（带同一帧历史点）。注入手势时用虚拟时间戳，别靠 sleep 估速度。

## 2026-10-19：字体不随应用走、按钮字距被撑开、全角间隔号

- **字体**：相位以前没带字体，全交给系统默认。手机上选了什么系统字体，相位就是什么样（用户看到的“楷体”多半来自这里；这台 ColorOS 16 的默认中文是 OPPO Sans，黑体类）。现在随应用带 Noto Sans SC 裁剪版（`res/font/phase_sans_sc.ttf`，`tools/build_phase_font.py` 可重新生成）。字库里没有的字仍由系统字体兜底，所以新增中文文案后要重新运行脚本，它会从源码里收集用到的字。
- **按钮字被撑开**：Material 的按钮文字用 `labelLarge`，而它原来被改成“小节标题”的 12sp、字距 2sp，于是所有文字按钮都带宽字距。小节标题现在是单独的 `EyebrowStyle`，`labelLarge` 恢复成普通按钮字阶。以后别把装饰性样式塞进 Material 的标准字阶。
- **灰紫色卡片**：没设 `surfaceContainer*` 时，`Card`、`AlertDialog`、`Switch` 会退回 Material 默认的灰紫色。颜色方案已补全。
- **全角间隔号**：中文字体里“·”（U+00B7）是全角字形，“5 个周期 · 7 小时”中间会空一大块，脚本里把它缩窄了。字体里还有 U+2022、U+2027、U+30FB 指向同一字形，一并受影响。
- **测试**：界面测试里依赖“某段文字在首屏”“第一个匹配的按钮”的写法，在版面调整后会失效；改成取相对位置（首屏标题之后、按钮之下最靠上的匹配），并在需要时先回到页面顶部。

## 2026-10-19：字体“换一个”和“分层”是两回事

用户前后三次反馈：原来的字体像楷体不对；换成思源黑体“全是黑体不好看”；四套整体方案“没有理解我的意思”。他要的是**同一页里不同位置用不同字体**。**教训**：用户说“字体单调”时，先想到的是角色分工（数字、标题、正文、招牌各用什么），而不是挑一个更好的整体字体；一次只给一种整体方案也没有用。现在的分工见 [1.4.5 报告](1.4.5/REPORT.md)。得意黑只有一个字重，样式里不要给它 SemiBold/Bold（Compose 会在原字形上再加粗，很糊）。

## 2026-10-19：黑体在短标签上显得笨重

用户指出“正常、爽睡、小睡”这类短模式名、状态行和标题用黑体“笨重”。**教训**：把某个字体设成“界面默认”，等于让它出现在所有小而短的标签上，而黑体的笔画粗，恰好最不适合。分层时应让**默认字体偏轻**（宋体），把粗重的字体留给少数需要它的地方（成段说明）。按字阶（bodyLarge、labelLarge 等）整体换字体，比逐个控件指定更不容易漏。详见 [1.4.6 报告](1.4.6/REPORT.md)。
