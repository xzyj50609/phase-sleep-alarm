# 1.4.2：卡片与滑块一起动、切换有过渡

2026-10-19 用户反馈 1.4.1：轻轻滑一下下面的卡片，上面的模式就整个切换，上下没有同步；上方滑块切换也没有渐变，很僵硬。手势方向沿用 1.4.1 已确认的取舍：在下方推荐卡片上左右划，上方滑块跟着动，不是上下滚动切模式。

## 原因

以下来自读代码，只有前两项在模拟器上用旧版复现过（见 [旧版基线](evidence/red-baseline.json)）。

1. **很短的快划也会切换**（已复现）：旧规则是松手速度够快就切，没有最小距离。24dp 的轻轻一划就换了模式，而卡片本身只挪了一点点，所以上下对不上。
2. **文字颜色瞬间翻转**（已复现）：滑块块用 0.24 秒滑过去，但文字颜色按「是否已选中」在第一帧就变了。滑块块刚起步，新名字已是选中色、旧名字已是灰色，灰字压在滑块块上几乎看不清。
3. 卡片的位移与滑块的进度是各算各的；松手后卡片弹回原位，内容却已瞬间换成新模式，没有过渡。

## 改动

- 卡片拖动与滑块共用一个进度：拖 144dp，滑块块刚好走一格。卡片跟手并随位移变淡。
- 拖过半格（72dp）松手才切换；快甩需同时满足速度不低于 1000dp/s、且拖过约 40dp。未达到则卡片与滑块一起弹回原位，模式不变。测速改为带同一帧里的历史点。
- 切换时（不论来自卡片、点滑块还是拖滑块）旧卡片滑出并淡出（110 毫秒），新模式卡片从另一侧滑入并淡入（220 毫秒），卡片高度变化平滑过渡。
- 滑块块改为弹簧动画；文字颜色随滑块块实际位置渐变，不再按「已选中」跳变。
- 滑出中的旧卡片按它自己的模式显示，并且不响应「设为系统闹钟」，设闹钟只认当前选中模式的那张。
- 版本升到 `1.4.2 (19)`，共存包显示 `1.4.2-test`，包名仍为 `com.example.smartalarm.test`，可覆盖 1.4.1 测试版（签名证书一致）。

数值（拖动距离、阈值、过渡时长）是我定的初值，常量集中在 `SwipeModeCard.kt` 顶部，手机上手感不对可直接调。

未改睡眠推荐算法、Root 与时钟桥接逻辑，未增加依赖，未推送或发布。slider 的手指直接拖动逻辑未改。

### 需要知道的情况

- 模拟器的系统动画默认是**关闭**（`animator_duration_scale=0`），此前 31 项回归一直在无动画下运行，对这类过渡问题没有检出能力。新增的动画类测试显式把动画调为 1、10 或 0，并在结束时还原。
- 第一版颜色测试因固定等待 250 毫秒，读到「尚未变化」的画面，在旧版误通过。已改成轮询截图、等滑块块起步再取色，上表是改后的结果。

## 手机验收

1. 覆盖安装「相位·测试版」，首页或设置里能读出 `1.4.2`。
2. 在下方大卡片上慢慢向左拖一小段：卡片跟手变淡，上方滑块块同步挪一点；松手后两边一起回原位，模式不变。
3. 拖过约一个指头宽再松手：旧卡片淡出，新卡片从右侧滑入，滑块块平滑滑到下一格，文字颜色渐变。
4. 很短的轻划不切换；明显的快划只切一个模式。第一个模式向右、最后一个模式向左有阻力，不绕圈。
5. 点上方名字、直接拖滑块：卡片同样淡出淡入，停下后上下是同一个模式。
6. 上下滚动页面不切模式；在按钮上横划不会设闹钟。
7. 觉得拖动距离、快甩速度、过渡快慢不合手，告诉我，调常量即可。
